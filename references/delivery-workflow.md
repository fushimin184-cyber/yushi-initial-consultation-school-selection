# 文件交付流程

1. 保留原有选校内容、中文内部标题与版式，只将下载文件名设为简短 ASCII 英文/数字/下划线/连字符（最长 96 字符，不含扩展名），例如 `Plan_20261008_v2.docx`。目录可以含中文。
2. 运行 `python scripts/build_plan.py --input <private-input.json> --output <absolute-path>/Plan_20261008_v2.docx`。脚本创建缺失目录，在临时文件中保存并检查：非空可读、ZIP CRC、必需 OOXML 部件、XML 可解析、python-docx 重开、正文 XML 与保存前一致。
3. 脚本生成同名 ZIP，仅包含通过检查的 DOCX，校验归档内容与 DOCX 字节一致；验证成功后替换目标文件。单个文件替换是原子的，DOCX/ZIP 两个文件不是跨文件事务；ZIP 发布失败会移除旧 ZIP 并抛错，旧 PDF 在 DOCX 发布前清除；进程被强制中断后仍应重新运行并复核，不能使用半套输出。
4. 读取标准输出 JSON，核对 `docx` / `zip` 中的实际绝对 `path`、`bytes` 和 `sha256`。交付前再次检查文件存在、非空、可读且校验值没有变化。JSON 只是本地验证记录，不证明上传、保存或客户端下载成功。
5. 继续执行原有逐页渲染检查；完整性检查不证明版式没有截断、字体正确或 Word 客户端兼容。完成适用环境的持久保存，再用真实路径提供 DOCX 与 ZIP 备用链接。公开仓库不存学生输入、生成文件、含学生信息的日志或清单。

## 用户明确要求 PDF

加入 `--pdf`，需要 LibreOffice/soffice 和 `pypdf`。使用独立临时配置目录转换，检查 PDF 非空、可解析、至少一页且每页可读取，并检查 DOCX 正文中文字符在 PDF 提取文本中保留。该检查能发现常见缺字，仍需逐页视觉检查。安装文档使用的中文字体（默认 Noto Sans CJK SC）；字体缺失或文本提取失败不得宣称 PDF 可交付。转换失败或超时会返回 `pdf_error` 并以非零状态退出；DOCX 与 ZIP 仍可用，明确说明 PDF 尚未生成，不提供 PDF 链接。重新生成 DOCX 会清除同名旧 PDF，避免交付过时版本。只有明确归属于本次交付的同名文件才可作为输出目标。

## Word 无法预览或下载

先检查实际文件与大小/校验值，重新打开 DOCX、测试 ZIP。若损坏则重新生成；若通过，保持最新正文、版式和选校内容，以新短英文文件名重新保存和验证，提供新的 DOCX 与 ZIP 链接。用户要求 PDF 时补充转换；不要自动把无法预览归因于内容损坏，也不要反复返回旧失效链接。

可通过代码控制：命名、保存、路径存在性、可读性、OOXML/CRC 检查、重开验证、ZIP 一致性、PDF 转换状态。
无法通过这些代码保证：ChatGPT 附件上传/保存是否成功、链接生命周期、iOS 或网页预览、客户端缓存及下载传输。ZIP 备用也可能受同一传输问题影响。若保存或下载仍失败，明确报告当前验证范围与交付限制，不宣称已解决界面问题。
